# 가. 데이터베이스 및 DBMS 개념
## 1. 데이터베이스(DB) : 컴퓨터를 사용하여 저장하고 관리하는 데이터의 집합
## 2. DBMS : DB를 운영 및 관리하는 소프트웨어(예: MySQL, MariaDB, Oracle 등)로, 표(Table) 형식의 레코드(행)와 필드(열) 형태로 데이터를 다룸
## 3. 엑셀 vs DB : 엑셀은 1인 작업 위주의 스프레드시트인 반면, DB는 여러 사용자 및 응용 프로그램의 동시 접속과 안전한 데이터 공유를 지원

# 나. MySQL 개요 및 환경 확인
## 1. MySQL 특징 : 오픈소스 기반의 세계적으로 널리 쓰이는 RDBMS로 신뢰성과 사용성이 높음
## 2. 에디션 구분 : 교육 및 실습용으로 쓰이는 무료 Community Edition과 대기업용 유료 Enterprise Edition으로 구분
## 3. Workbench 확인 : 실행 후 기본 계정 로그인 시 sakila, world, sys 등의 샘플 데이터베이스가 탑재

# 다. 정보시스템 구축 5단계 (SDLC)
## 1. 요구 사항 분석 : 고객/업무 담당자의 요구사항 수집 및 정리단계
## 2. 시스템 설계 (핵심) : 화면 설계 및 데이터베이스 설계도(ERD) 작성단계
## 3. 프로그램 구현 : 설계도를 바탕으로 SQL 테이블 생성 및 코딩을 진행

## 5. 유지보수 : 시스템 오픈 후 발생 오류 수정 및 기능을 제어

# 라. 데이터 모델링과 ERD
## 데이터 불일치를 방지하고 무결성을 유지하기 위해 복잡한 데이터를 여러 테이블(회원, 상품, 주문 등)로 세분화(정규화)하여 관리
  * 모델 (Model) : 현실 세계 데이터를 단순화하여 정제한 구조의 틀(결과물 = 테이블)
  * 모델링 (Modeling) : 요구사항을 분석하여 데이터 구조로 변환하는 전체 프로세스(행위)
  * ERD (Entity-Relationship Diagram) : 테이블 간의 구조와 관계(1:1, 1:N, N:M)를 한눈에 보여주는 시각화 설계도

# 마. DB 모델링 필수 용어
## 1. 엔티티 (Entity) : 관리하고자 하는 현실 세계의 대상
  * 테이블 (Table)
  * ex) 회원, 상품, 주문
## 2. 속성 (Attribute) : 엔티티가 가질 수 있는 세부 특징/항목
  * 컬럼 (Column/Field)
  * ex) 회원 이름, 아이디, 이메일
## 3. 관계 (Relationship) : 엔티티 간의 연관성 및 규칙
  * 1:1, 1:N, N:M 관계
  * ex) 주문한다, 소속된다
## 4. 주식별자 (PK) : 행을 유일하게 구별할 수 있는 대표 속성
  * Primary Key
  * ex) 회원ID, 학번, 사원번호

# 바. DB 모델링 3단계 진행 과정
## 1. 개념적 모델링: 업무 분석 후 핵심 엔티티와 관계를 추출하여 ERD(개념도) 작성
## 2. 논리적 모델링: ERD를 테이블 구조로 변환하고 속성과 기본키(PK) 등을 정의
## 3. 물리적 모델링: DBMS(MySQL) 특성에 맞춰 구체적인 데이터 형식(INT 등) 지정

# 사. SQL 개요 및 명령어 종류
## 1. SQL (Structured Query Language) : 관계형 데이터베이스에 정보를 저장, 수정, 삭제, 조회하기 위한 표준 프로그래밍 언어
## 2. 주요 SQL 명령어 분류
### 가) DDL (Data Definition Language / 데이터 정의어) : 데이터베이스, 테이블 등 데이터베이스 스키마(구조)를 생성, 변경, 삭제하는 명령어
  * SHOW : 데이터베이스나 테이블의 목록을 확인
    * ex) SHOW DATABASES;, SHOW TABLES;
  * CREATE : 새로운 데이터베이스나 테이블을 생성
    * ex) CREATE DATABASE testdb;, CREATE TABLE test_table (...);
  * ALTER: 기존 데이터베이스의 속성이나 테이블의 컬럼(데이터 타입, 제약조건 등)을 변경
  * DROP : 기존 데이터베이스나 테이블을 삭제
    * ex) DROP DATABASE testdb;, DROP TABLE test_table;
### 나) DML (Data Manipulation Language / 데이터 조작어) : 테이블 내의 실제 데이터를 조회, 추가, 수정, 삭제할 때 사용하는 명령어
  * SELECT : 테이블에서 저장된 데이터를 조회
    * ex) SELECT * FROM test_table;
  * INSERT : 테이블에 새로운 데이터(행)를 삽입
    * ex) INSERT INTO test_table (col2, col3) VALUES ('입력데이터', '2026-01-01');
  * UPDATE : 테이블에 저장되어 있는 기존 데이터를 수정
    * ex) UPDATE test_table SET col2 = '수정' WHERE col1 = 3;
  * DELETE : 테이블 내의 특정 데이터(행)를 삭제
    * ex) DELETE FROM test_table WHERE col1 = 2;

# 아. 테이블 속성
## 1. 기본키 (Primary Key, PK)
  * 테이블에서 각 행(Row)을 고유하게 식별하기 위해 사용하는 컬럼(또는 컬럼의 조합)
  * 특징: 중복 불가능(UNIQUE) + NULL 허용 안 함(NOT NULL)
  * 한 테이블당 하나만 지정
  * AUTO_INCREMENT
    * 주로 `PRIMARY KEY` 정수형 컬럼(고유 ID)에 사용됨
    * 기능: 새로운 행이 추가될 때마다 고유한 정수 번호가 1씩 자동으로 증가하여 할당
    * 특징
      * 개발자가 직접 번호를 부여할 필요가 없어 관리가 용이함(고유 ID 자동 생성)
      * 정수형(`INT`) 컬럼에만 지정 가능하며, 테이블당 단 1개의 컬럼만 설정 가능
## 2. 외래키 (Foreign Key, FK)
  * 다른 테이블의 기본키(PK)를 참조하여 테이블 간의 관계를 형성하는 컬럼
  * 참조 무결성(Referential Integrity)을 보장하여, 참조하는 테이블에 존재하지 않는 데이터를 입력할 수 없도록 방지

# 자. 데이터 조회
## 1. 기본 (SELECT, WHERE)
### 가) 데이터베이스에서 데이터를 조회할 때 가장 기본이 되는 구문
  * 기본 문법
    * SELECT 컬럼명1, 컬럼명2 FROM 테이블명;
    * SELECT * FROM 테이블명; (전체 컬럼 조회)
  * 조건 필터링 (WHERE)
    * 비교 연산자: =, !=, >, <, >=, <=
    * 논리 연산자: AND, OR, NOT
    * 예시: SELECT Name, Population FROM country WHERE Continent = 'Asia' AND Population >= 50000000;
## 2. 범위, 목록, 패턴 검색 (BETWEEN, IN, LIKE)
### 가) BETWEEN
  * 구문 : BETWEEN A AND B
  * 설명 : A 이상 B 이하 범위 검색
  * 예시 : WHERE Population BETWEEN 10000000 AND 20000000
### 나) IN
  * 구문 : IN (값1, 값2...)
  * 설명 : 지정한 목록 중 하나라도 일치할 때
  * 예시 : WHERE Continent IN ('Asia', 'Europe')
### 다) LIKE
  * 구문 : LIKE '김%', LIKE '김_'
  * 설명 : 문자열 패턴 검색 (와일드카드 활용)
  * 예시 : WHERE Name LIKE 'South%'
  * 와일드 카드
    * % : 글자 수 제한 없이 모든 문자 허용 ('김%' $\rightarrow$ 김으로 시작하는 모든 글자)
    * _ : 언더바 개수만큼의 글자 수 강제 ('김_' $\rightarrow$ 김으로 시작하는 2글자)
## 3. 정렬 및 개수 제한 (ORDER BY, LIMIT)
### 가) ORDER BY (정렬)
  * 오름차순: ASC (기본값)
  * 내림차순: DESC
### 나) LIMIT (개수 제한)
  * 상위 N개 데이터만 추출할 때 사용
### 다) 예시 : 인구수 기준 상위 5개 국가 조회
  * SELECT Name, Population FROM country 
  ORDER BY Population DESC 
  LIMIT 5;
## 4. 주요 집계 함수 & 데이터 그룹화 (GROUP BY, HAVING)
### 가) 주요 집계 함수
  * COUNT() : 레코드 개수 반환 (NULL 포함 시 COUNT(*))
  * SUM() / AVG() : 합계 / 평균 (NULL 제외)
  * MAX() / MIN() : 최댓값 / 최솟값 (NULL 제외)
### 나) 그룹화 (GROUP BY & HAVING)
  * GROUP BY : 특정 컬럼 값이 같은 데이터끼리 묶어서 그룹별 집계 통계를 낼 때 사용
  * WHERE vs HAVING 차이점
    * WHERE : 그룹화하기 전 개별 행(Row) 단위 1차 필터링 (집계 함수 사용 불가)
    * HAVING : 그룹화된 결과(Group BY)에 대한 2차 필터링 (집계 함수 조건 사용 가능)
  * 예시
    * SELECT Continent AS 대륙, SUM(Population) AS 총인구수
    FROM country
    GROUP BY Continent
    HAVING 총인구수 >= 500000000
    ORDER BY 총인구수 DESC;

# 차. 조건부 데이터 입력 및 수정
## 1. 개요 : 데이터를 입력할 때 중복이 발생할 경우, 에러를 무시하고 건너뛰거나 기존 데이터를 업데이트하는 구문입니다.
## 2. INSERT IGNORE
  * 개념: 데이터 입력 시 기본키(PK) 중복 에러가 발생하면, 에러를 무시하고 해당 행의 삽입을 건너뜁니다 (Skip).
## 3. ON DUPLICATE KEY UPDATE
  * 개념: 기본키(PK) 중복 여부에 따라 동작을 달리합니다.
    * 기본키 중복 X: 신규 데이터 삽입(INSERT) 수행
    * 기본키 중복 O: 기존 데이터를 지정한 값으로 자동 수정(UPDATE) 수행

# 카. MySQL 주요 데이터 타입 세부 정리
## 1. 정수형
  * 데이터 타입 : TINYINT, SMALLINT, INT, BIGINT
  * 설명 및 범위
    * INT: 4 Byte (약 -21억 ~ 21억)
    * BIGINT: 8 Byte (대용량 ID, 금액 등에 사용)
## 2. 실수형
  * 데이터 타입 : FLOAT, DOUBLE, DECIMAL
  * 설명 및 범위 : DECIMAL(P, S): 오차가 없는 정확한 실수 표현
## 3. 문자형
  * 데이터 타입 : CHAR(N), VARCHAR(N), TEXT, LONGTEXT
  * 설명 및 범위
    * CHAR: 고정 길이 문자열
    * VARCHAR: 가변 길이 문자열
    * LONGTEXT: 최대 4GB 대용량 텍스트
## 4. 날짜/시간형
  * 데이터 타입 : DATE, TIME, DATETIME
  * 설명 및 범위
    * DATE: YYYY-MM-DD 형식
    * DATETIME: 날짜 및 시분초 포함

# 파. 명시적 형변환과 묵시적 형변환
## 1. 명시적 형변환 (Explicit Conversion)
### 가) 개요 : 개발자가 함수를 사용하여 데이터 타입을 직접 강제로 변경하는 방식
### 나) 기본 문법
  * CAST(값 AS 데이터타입)
  * CONVERT(값, 데이터타입)
### 다) 핵심 주의사항 (타입 지정 제약)
  * 테이블 생성 시 사용하는 일반 타입(INT, VARCHAR, FLOAT 등)을 형변환 함수 안에 그대로 사용하면 문법 에러(Syntax Error)가 발생
  * 형변환 함수 내부에서는 반드시 전용 타입을 사용
    * 정수형 변환 시: SIGNED 또는 UNSIGNED 사용 (INT 사용 불가)
    * 문자열형 변환 시: CHAR 또는 CHAR(N) 사용 (VARCHAR 사용 불가)
    * 실수형 변환 시: DECIMAL 사용 (FLOAT, DOUBLE 사용 불가)
## 2. 묵시적 형변환 (Implicit Conversion)
### 가) 개요 : 사용자가 직접 형변환 함수를 쓰지 않아도, 연산자나 문맥에 따라 MySQL이 데이터 타입을 자동으로 판단하여 변환해 주는 기능
  * 예시: SELECT '100' + '200'; $\rightarrow$ 문자열이 자동으로 숫자로 계산되어 300 결과 출력

# 거. 조인 (JOIN)
## 1. 개요 : 여러 테이블로 나뉘어 저장된 데이터를 공통 컬럼(PK-FK)을 매개체로 하나로 합쳐서 조회하는 기술입니다
### 가) INNER JOIN (내부 조인)
  * 개념 : 두 테이블 모두에 공통으로 존재하는 데이터만 결합하여 추출 (교집합)
  * 특징 : 기준 키 값이 어느 한쪽에만 있거나 NULL인 행은 결과에서 제외
  * 예시 : '주문 이력이 있는 회원'의 정보만 조회할 때 사용
  * SELECT M.user_id, M.user_name, B.prod_name
  FROM member M
  INNER JOIN buy B ON M.user_id = B.user_id;
### 나) LEFT / RIGHT OUTER JOIN (외부 조인): 한쪽 기준 테이블의 모든 데이터 + 매칭되는 데이터 결합 (매칭 데이터 없으면 NULL 표시)
  * 개념 : 왼쪽/오른쪽(기준) 테이블의 모든 데이터를 출력하고, 오른쪽/왼쪽 테이블에서 일치하는 값이 있으면 가져옴
  * 특징 : 오른쪽/왼쪽 테이블에 매칭되는 데이터가 없으면 해당 컬럼은 NULL로 채워짐
  * 예시 : '구매 이력이 없는 회원을 포함한' 전체 회원 목록과 구매 내역을 조회할 때 사용
  * SELECT M.user_id, M.user_name, B.prod_name
  FROM member M
  LEFT JOIN buy B ON M.user_id = B.user_id;
  * SELECT M.user_id, M.user_name, B.prod_name
  FROM member M
  RIGHT JOIN buy B ON M.user_id = B.user_id;
### 다) CROSS JOIN (상호 조인): 조인 조건 없이 모든 경우의 수 조합 (A 행 수 $\times$ B 행 수)
  * 개념 : 한쪽 테이블의 모든 행과 다른 쪽 테이블의 모든 행을 1:1로 가능한 모든 조합으로 결합
  * 특징: 별도의 조인 조건(ON)이 필요 없으며, 결과 행의 개수는 A 테이블 행 수 × B 테이블 행 수. 테스트용 대량 데이터를 생성할 때 주로 활용
### 라) SELF JOIN (자체 조인): 자기 자신 테이블과의 조인 (계층 구조 표현 시 사용)
  * 개념 : 별도의 조인 구문이 따로 존재하는 것이 아니라, 자기 자신(동일한 테이블)과 다시 조인
  * 특징 : 테이블 별칭(Alias) 필수: 같은 테이블을 두 번 이상 불러와서 결합하므로, 구분을 위해 테이블에 반드시 서로 다른 별칭(예: A, B 또는 emp, mgr)을 부여
  * 예시 
  * SELECT 
  E.emp_name AS "직원명",
  M.emp_name AS "상사명"
  FROM employee E
  LEFT JOIN employee M ON E.manager_id = M.emp_id;
