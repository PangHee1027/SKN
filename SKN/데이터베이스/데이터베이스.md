# 가. 데이터베이스 및 DBMS 개념
## 1. 데이터베이스(DB) : 컴퓨터를 사용하여 저장하고 관리하는 데이터의 집합
## 2. DBMS : DB를 운영 및 관리하는 소프트웨어(예: MySQL, MariaDB, Oracle 등)로, 표(Table) 형식의 레코드(행)와 필드(열) 형태로 데이터를 다룸
## 3. 엑셀 vs DB : 엑셀은 1인 작업 위주의 스프레드시트인 반면, DB는 여러 사용자 및 응용 프로그램의 동시 접속과 안전한 데이터 공유를 지원

# 나. MySQL 개요 및 환경 확인
## 1. MySQL 특징 : 오픈소스 기반의 세계적으로 널리 쓰이는 RDBMS로 신뢰성과 사용성이 높음
## 2. 에디션 구분 : 교육 및 실습용으로 쓰이는 무료 Community Edition과 대기업용 유료 Enterprise Edition으로 구분
## 3. Workbench 확인 : 실행 후 기본 계정 로그인 시 sakila, world, sys 등의 샘플 데이터베이스가 탑재

# 다. 정보시스템 구축 5단계 (SDLC)
## 1. 요구 사항 분석 : 고객/업무 담당자의 요구사항 수집 및 정리단계
## 2. 시스템 설계 (핵심) : 화면 설계 및 데이터베이스 설계도(ERD) 작성단계
## 3. 프로그램 구현 : 설계도를 바탕으로 SQL 테이블 생성 및 코딩을 진행
## 4. 테스트 : 버그 및 요구사항 충족 여부를 검증
## 5. 유지보수 : 시스템 오픈 후 발생 오류 수정 및 기능을 제어

# 라. 데이터 모델링과 ERD
## 데이터 불일치를 방지하고 무결성을 유지하기 위해 복잡한 데이터를 여러 테이블(회원, 상품, 주문 등)로 세분화(정규화)하여 관리
  * 모델 (Model) : 현실 세계 데이터를 단순화하여 정제한 구조의 틀(결과물 = 테이블)
  * 모델링 (Modeling) : 요구사항을 분석하여 데이터 구조로 변환하는 전체 프로세스(행위)
  * ERD (Entity-Relationship Diagram) : 테이블 간의 구조와 관계(1:1, 1:N, N:M)를 한눈에 보여주는 시각화 설계도

# 마. DB 모델링 필수 용어
## 1. 엔티티 (Entity) : 관리하고자 하는 현실 세계의 대상
  * 테이블 (Table)
  * ex) 회원, 상품, 주문
## 2. 속성 (Attribute) : 엔티티가 가질 수 있는 세부 특징/항목
  * 컬럼 (Column/Field)
  * ex) 회원 이름, 아이디, 이메일
## 3. 관계 (Relationship) : 엔티티 간의 연관성 및 규칙
  * 1:1, 1:N, N:M 관계
  * ex) 주문한다, 소속된다
## 4. 주식별자 (PK) : 행을 유일하게 구별할 수 있는 대표 속성
  * Primary Key
  * ex) 회원ID, 학번, 사원번호

# 바. DB 모델링 3단계 진행 과정
## 1. 개념적 모델링: 업무 분석 후 핵심 엔티티와 관계를 추출하여 ERD(개념도) 작성
## 2. 논리적 모델링: ERD를 테이블 구조로 변환하고 속성과 기본키(PK) 등을 정의
## 3. 물리적 모델링: DBMS(MySQL) 특성에 맞춰 구체적인 데이터 형식(INT 등) 지정

# 사. SQL 개요 및 명령어 종류
## 1. SQL (Structured Query Language) : 관계형 데이터베이스에 정보를 저장, 수정, 삭제, 조회하기 위한 표준 프로그래밍 언어
## 2. 주요 SQL 명령어 분류
### 가) DDL (Data Definition Language / 데이터 정의어) : 데이터베이스, 테이블 등 데이터베이스 스키마(구조)를 생성, 변경, 삭제하는 명령어
  * SHOW : 데이터베이스나 테이블의 목록을 확인
    * ex) SHOW DATABASES;, SHOW TABLES;
  * CREATE : 새로운 데이터베이스나 테이블을 생성
    * ex) CREATE DATABASE testdb;, CREATE TABLE test_table (...);
  * ALTER: 기존 데이터베이스의 속성이나 테이블의 컬럼(데이터 타입, 제약조건 등)을 변경
  * DROP : 기존 데이터베이스나 테이블을 삭제
    * ex) DROP DATABASE testdb;, DROP TABLE test_table;
### 나) DML (Data Manipulation Language / 데이터 조작어) : 테이블 내의 실제 데이터를 조회, 추가, 수정, 삭제할 때 사용하는 명령어
  * SELECT : 테이블에서 저장된 데이터를 조회
    * ex) SELECT * FROM test_table;
  * INSERT : 테이블에 새로운 데이터(행)를 삽입
    * ex) INSERT INTO test_table (col2, col3) VALUES ('입력데이터', '2026-01-01');
  * UPDATE : 테이블에 저장되어 있는 기존 데이터를 수정
    * ex) UPDATE test_table SET col2 = '수정' WHERE col1 = 3;
  * DELETE : 테이블 내의 특정 데이터(행)를 삭제
    * ex) DELETE FROM test_table WHERE col1 = 2;
# 아. 테이블 속성
## 1. 기본키 (Primary Key, PK)
  * 테이블에서 각 행(Row)을 고유하게 식별하기 위해 사용하는 컬럼(또는 컬럼의 조합)
  * 특징: 중복 불가능(UNIQUE) + NULL 허용 안 함(NOT NULL)
  * 한 테이블당 하나만 지정
  * AUTO_INCREMENT
    * 주로 `PRIMARY KEY` 정수형 컬럼(고유 ID)에 사용됨
    * 기능: 새로운 행이 추가될 때마다 고유한 정수 번호가 1씩 자동으로 증가하여 할당
    * 특징
      * 개발자가 직접 번호를 부여할 필요가 없어 관리가 용이함(고유 ID 자동 생성)
      * 정수형(`INT`) 컬럼에만 지정 가능하며, 테이블당 단 1개의 컬럼만 설정 가능
## 2. 외래키 (Foreign Key, FK)
  * 다른 테이블의 기본키(PK)를 참조하여 테이블 간의 관계를 형성하는 컬럼
  * 참조 무결성(Referential Integrity)을 보장하여, 참조하는 테이블에 존재하지 않는 데이터를 입력할 수 없도록 방지
